Part XVIIPractical Projects

Do these in order. Each assumes the last, and each turns a chapter you read into a program you wrote. Write them in C on Linux (or WSL/macOS) to feel the real system calls. Keep every project — later ones build on earlier code, and together they make a portfolio that proves you understand operating systems.

Beginner LEVEL 1

01 Process Creation Demo

Objective
Create a child process and print both PIDs, proving parent/child identity.
Concepts
Processes, PIDs, fork()'s double return (Part II).
Plan
Call fork(); branch on the return value; print getpid()/getppid() in each.
Milestones
(1) fork compiles & runs; (2) both branches print; (3) explain the output order's nondeterminism.
Expected
Two lines, one from parent (child's PID) and one from child (0-return path).
Extensions
Fork N children in a loop; build a small process tree and print it.

02 fork / wait Demonstration

Objective
Have the parent wait for the child and read its exit status.
Concepts
Termination, reaping, exit status, synchronization via wait (Part II).
Plan
Child does work and exit(k); parent waitpid()s and prints WEXITSTATUS.
Milestones
(1) parent blocks until child ends; (2) status decoded; (3) time the child to confirm the wait.
Expected
Parent prints the child's exit code after the child finishes.
Extensions
Wait for multiple children; detect a child killed by a signal (WIFSIGNALED).

03 Zombie Process Demonstration

Objective
Deliberately create a zombie and observe it, then eliminate it.
Concepts
Zombie processes, the process table, reaping (Part II).
Plan
Child _exit()s immediately; parent sleep(30) without wait.
Milestones
(1) run ps -el | grep defunct and find the <defunct> entry; (2) add wait(); (3) confirm the zombie is gone.
Expected
A visible zombie while the parent naps; none once reaped.
Extensions
Reap asynchronously with a SIGCHLD handler instead of a blocking wait.

04 Orphan Process Demonstration

Objective
Create an orphan and watch it get re-parented to PID 1.
Concepts
Orphans, re-parenting, PID 1 (Parts II, XV).
Plan
Parent exits first; child sleeps, then prints getppid() — now 1.
Milestones
(1) parent exits before child; (2) child's parent PID becomes 1; (3) explain who reaps it.
Expected
The child reports parent PID 1 (systemd) after the original parent dies.
Extensions
Turn the child into a proper daemon with setsid().

Intermediate LEVEL 2

05 Mini Shell

Objective
A REPL that runs commands: read a line, run the program, wait, repeat.
Concepts
The fork/exec/wait pattern, the shell loop (Part II).
Plan
Loop: print prompt → read line → tokenize → fork → child execvp → parent wait.
Milestones
(1) run ls; (2) handle arguments; (3) built-ins cd and exit.
Expected
A working prompt that runs external commands with arguments.
Extensions
Command history; background &; grow this into Project 16.

06 Producer–Consumer

Objective
Threads producing and consuming through a bounded buffer, correctly.
Concepts
Semaphores, mutex, bounded buffer (Part V).
Plan
Two counting semaphores (empty, full) + a mutex; producer/consumer threads.
Milestones
(1) single producer/consumer; (2) multiple of each; (3) verify no item lost/duplicated.
Expected
Every produced item consumed exactly once, no corruption, no deadlock.
Extensions
Swap semaphores for condition variables; benchmark throughput vs buffer size.

07 Thread-Safe Queue

Objective
A generic concurrent queue safe for many producers/consumers.
Concepts
Mutexes, condition variables, blocking semantics (Part V).
Plan
enqueue/dequeue guarded by a mutex; dequeue waits on a condvar when empty.
Milestones
(1) correct under 1+1 threads; (2) stress with 8+8; (3) clean shutdown signal.
Expected
No races or lost wakeups under heavy concurrent load.
Extensions
Bounded variant (block on full); lock-free version with CAS (Part V).

08 Readers–Writers

Objective
Allow concurrent readers but exclusive writers on a shared resource.
Concepts
Reader/writer coordination, starvation trade-offs (Part V).
Plan
Reader counter + counter mutex + resource semaphore; first-in/last-out reader logic.
Milestones
(1) many readers overlap; (2) a writer excludes all; (3) demonstrate writer starvation, then fix it.
Expected
Readers run in parallel; writers get exclusive access; data stays consistent.
Extensions
Implement writer-preference; compare fairness.

09 IPC Using Pipes

Objective
Two processes exchanging data through a pipe.
Concepts
Pipes, fds, closing unused ends, EOF (Part XI).
Plan
pipe() then fork(); parent writes, child reads and processes.
Milestones
(1) send one message; (2) stream many; (3) implement cmd1 | cmd2 with dup2.
Expected
Child receives exactly what the parent sent; clean EOF on writer close.
Extensions
Named pipe (FIFO) between two unrelated programs.

10 Shared-Memory Program

Objective
Two processes communicating via a shared memory segment, synchronized.
Concepts
Shared memory, mmap, semaphores for sync (Parts VIII, XI).
Plan
shm_open+mmap a region; a named semaphore orders writer→reader.
Milestones
(1) both map the same region; (2) writer's data visible to reader; (3) add the semaphore to fix races.
Expected
Reader sees exactly what the writer wrote, in order, no tearing.
Extensions
A ring buffer in shared memory; benchmark vs the pipe version.

Advanced LEVEL 3

11 Custom Memory Allocator

Objective
Implement your own malloc/free over a heap you request from the kernel.
Concepts
Heap, sbrk/mmap, free lists, fragmentation (Parts VII, XVI).
Plan
Grab memory with sbrk/mmap; manage blocks with headers; free-list allocation (first/best fit); coalesce on free.
Milestones
(1) allocate/free fixed sizes; (2) reuse freed blocks; (3) split & coalesce; (4) handle alignment.
Expected
A drop-in allocator that passes a stress test of random alloc/free without leaking or corrupting.
Extensions
Size classes / bins (like a real allocator); measure fragmentation.

12 Mini Scheduler Simulator

Objective
Simulate FCFS, SJF, SRTF, Priority, and Round Robin on a process table.
Concepts
Scheduling algorithms, metrics (Part IV).
Plan
Read (AT, BT[, priority]); simulate the clock; output Gantt order and average WT/TAT/RT.
Milestones
(1) FCFS correct; (2) add preemptive SRTF & RR with a quantum; (3) verify against the Part IV worked examples.
Expected
Matches the hand-computed numbers from Part IV for every algorithm.
Extensions
Add MLFQ; plot average waiting time vs quantum for RR.

13 Page-Replacement Simulator

Objective
Count page faults for FIFO, LRU, and Optimal on a reference string.
Concepts
Demand paging, replacement, Belady's anomaly (Part VIII).
Plan
Input reference string + frame count; simulate each policy; count faults.
Milestones
(1) FIFO; (2) LRU & Optimal; (3) reproduce Belady's anomaly with FIFO at 3 vs 4 frames.
Expected
Reproduces Part VIII's numbers (7/9/10) and demonstrates Belady.
Extensions
Add Clock/second-chance; sweep frame counts and plot the fault curve.

14 File-System Simulator

Objective
A tiny in-memory (or single-file) file system with inodes and a directory.
Concepts
Inodes, block allocation, free-space bitmap, directories (Part IX).
Plan
Model a superblock, inode table, data blocks, and a bitmap; implement create/write/read/delete/ls.
Milestones
(1) create & list files; (2) read/write via indexed blocks; (3) delete & reclaim blocks; (4) persist to a file.
Expected
A working mini-FS you can format, populate, unmount, and re-mount.
Extensions
Add indirect blocks for large files; add a simple journal.

15 Thread Pool

Objective
A fixed set of worker threads pulling tasks from a shared queue.
Concepts
Threads, thread-safe queue (Project 7), work distribution (Parts III, V).
Plan
Spawn N workers that block on your thread-safe queue; a submit(task) enqueues work; graceful shutdown.
Milestones
(1) workers run submitted tasks; (2) balanced load; (3) clean shutdown drains or cancels tasks.
Expected
Tasks execute concurrently across exactly N threads with no races.
Extensions
Return futures/results; dynamically size the pool by load.

16 Mini Unix Shell with Pipes & Redirection

Objective
Extend Project 5 into a real shell: pipelines and I/O redirection.
Concepts
fork/exec, pipe, dup2, fds, job control (Parts II, IX, XI).
Plan
Parse a | b | c and < in/> out; wire pipes with dup2; fork one child per stage.
Milestones
(1) single redirection; (2) two-command pipe; (3) N-stage pipeline; (4) background jobs & SIGINT handling.
Expected
cat file | grep foo | sort > out.txt works end to end.
Extensions
jobs/fg/bg; globbing; environment variables.
⚑Interview Tip
Projects 5/16 (a shell), 11 (an allocator), and 15 (a thread pool) are gold for interviews: they're common "implement this" prompts and instant credibility on a resume. If you build only three from this list, build those — and be ready to explain every system call and synchronization decision in them.

Progression goals

  1. Level 1 done when you can create, wait for, and reason about processes and can produce/eliminate a zombie and an orphan on purpose.
  2. Level 2 done when you have a working shell, a correct producer–consumer and readers–writers, and can move data by both pipe and shared memory.
  3. Level 3 done when your allocator, scheduler and page-replacement simulators match this book's worked numbers, and your shell runs real pipelines.
Portfolio Bar
A single repository containing your shell (16), allocator (11), thread pool (15), and the two simulators (12, 13), each with a short README explaining the OS concepts it demonstrates, is a genuinely strong systems-programming portfolio.

Mastered when… you can start any of these from a blank file, explain each system call as you type it, and debug it with strace/gdb when it misbehaves.
