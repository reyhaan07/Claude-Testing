One-Page OS Cheat Sheet

▣The Whole Book in One Box
OS = resource manager + extended machine. Kernel runs privileged; apps run restricted; cross via syscall / interrupt / exception.
Process = program in execution (own address space, PCB). Thread = flow inside a process (shares code/data/heap; own stack/regs/PC).
States: New→Ready→Running→(Waiting)→Terminated. fork=copy (COW), exec=replace image, wait=reap.
Scheduling: FCFS (convoy), SJF/SRTF (optimal WT, starves), RR (response/fairness, quantum), Priority (+aging), MLFQ (adaptive).
Sync: mutex (owned) / semaphore (counter, signaling); protect the critical section; producer–consumer = empty/full + mutex.
Deadlock: mutual exclusion + hold-and-wait + no-preemption + circular-wait; break one (lock ordering). Banker's = avoidance.
Memory: virtual→physical via MMU; page+offset; TLB caches translations; multi-level page tables save space.
Virtual memory: demand paging; page fault loads from disk; replace with FIFO/LRU/Optimal; too much paging = thrashing.
Files: directory(name)→inode(metadata+blocks)→data; hard link shares inode, symlink stores a path; journaling = crash-safe.
I/O: polling < interrupt < DMA; buffer (in transit) vs cache (duplicate). IPC: shared memory (fast, sync yourself) vs message passing (safe).
Disk: FCFS/SSTF/SCAN/C-SCAN/LOOK/C-LOOK; RAID 0=speed,1=mirror,5=parity(1),6=(2),10=both. Net: socket=fd; TCP reliable/stream, UDP fast/datagram; epoll scales.

Key Definitions (Rapid Recall)

Kernel: privileged core of the OS. System call: controlled kernel entry for a service. Process: program in execution with its own address space. Thread: schedulable flow sharing a process's memory. PCB: kernel record of a process's full state. Context switch: save one process's state, restore another's. Critical section: code touching shared data, one thread at a time. Race condition: outcome depends on thread timing. Mutex: owned lock for mutual exclusion. Semaphore: counter with atomic wait/signal. Deadlock: circular wait, all blocked forever. Starvation: a process indefinitely denied service. Livelock: busy but no progress.

Virtual memory: illusion of large private memory backed by disk. Page fault: referenced page not in RAM. TLB: cache of recent address translations. Thrashing: more time paging than executing. Working set: pages a process uses recently. Locality: tendency to reuse nearby/recent data. Inode: file metadata + block pointers (no name). DMA: device↔RAM transfer without the CPU. Copy-on-write: share pages until a write copies one. Spinlock: lock that busy-waits. Daemon: background service, no terminal. Zombie: dead process not yet reaped. Orphan: running process whose parent died.

Common Interview Traps

⚠The Misconceptions That Cost Offers
  1. "malloc is a system call." No — a library allocator; only sometimes calls brk/mmap.
  2. "A binary semaphore is a mutex." No — a mutex has ownership; a semaphore doesn't.
  3. "You can kill a zombie." No — it's already dead; reap it (or kill the parent).
  4. "Waiting goes straight to Running." No — it goes to Ready, then must be scheduled.
  5. "A program switches itself to kernel mode." No — only via syscall/interrupt/exception.
  6. "More frames always means fewer faults." Not for FIFO — Belady's anomaly.
  7. "A RAG cycle always means deadlock." Only with single-instance resources.
  8. "Threads have their own heap." No — the heap is shared; only the stack is per-thread.
  9. "Low free RAM is bad." No — it's page cache; watch available.
  10. "DMA eliminates interrupts." No — it reduces them to ~one per block.
  11. "TCP preserves message boundaries." No — it's a byte stream; delimit yourself.
  12. "RAID is a backup." No — it survives disk failure, not deletion/corruption.
  13. "Optimal page replacement is usable." No — it needs the future; it's a benchmark only.
  14. "Spinlocks are always fast." No — disastrous on a single core / long holds.
  15. "exec creates a new process." No — it replaces the current one (same PID); fork creates.
