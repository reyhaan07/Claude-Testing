Part XVIIIInterview Mastery

These are the questions, in the words interviewers actually use. Read the model answer, then close the book and say it in your own words — fluency, not recognition, is what's tested. Answers are deliberately compact: enough to be correct and complete, short enough to memorize the shape of.

Level 1 — Beginner FUNDAMENTALS

What is an operating system?
Software that manages hardware resources and provides an abstraction layer so programs use the hardware safely and portably. Two jobs: resource manager (CPU, memory, devices) and extended machine (files, processes, virtual memory).
What is a kernel?
The core of the OS — always resident, runs in privileged mode, and directly manages processes, memory, and devices. When we say "the OS did X," we usually mean the kernel.
Difference between user mode and kernel mode?
Kernel mode can run any instruction and access all memory/devices; user mode is restricted (no privileged instructions, only its own memory). Applications run in user mode; the kernel in kernel mode. The switch happens via syscall, interrupt, or exception. Trap: a program can't switch itself — only those three hardware-mediated doorways cross the line.
Program vs process?
A program is a passive file on disk; a process is a program in execution with its own memory, registers, PC, and PID. One program → many processes.
Process vs thread?
A process has its own address space; threads live inside a process and share its code, data, and heap, keeping only their own stack, registers, and PC. Threads are cheaper to create and switch; a process crash is isolated, a thread crash can take down the whole process.
What is a system call?
The controlled entry point through which a user program requests a kernel service (open, read, fork). It traps into kernel mode, runs the service, and returns. It's the only way to do anything privileged.
API vs system call?
An API is the function set your code calls (libc's printf, fopen); a system call is the kernel entry beneath (write, open). APIs may wrap zero, one, or many syscalls.
What are the process states?
New, Ready, Running, Waiting/Blocked, Terminated. Ready→Running is dispatch; Running→Ready is preemption; Running→Waiting is blocking on I/O; Waiting→Ready is wakeup. Trap: Waiting goes to Ready, not straight to Running.
What is a PCB?
Process Control Block — the kernel structure holding all state of a process: PID, state, PC, registers, scheduling info, memory maps, open files. It's what a context switch saves and restores.
What is context switching?
Saving the running process's state (registers, PC) into its PCB and restoring another's, so the CPU can switch processes. It's overhead — no application work happens during the switch.
What does fork() do?
Creates a near-exact copy of the calling process (the child). Returns twice: child's PID to the parent, 0 to the child. Uses copy-on-write so it's cheap.
What does exec() do?
Replaces the current process's memory image with a new program (same PID). Doesn't return on success. Combined with fork, it's how shells launch commands.
Zombie vs orphan process?
A zombie has terminated but its parent hasn't reaped it (wasting a PCB slot); an orphan is still running but its parent died (adopted by PID 1). Trap: you can't kill -9 a zombie — it's already dead; kill the parent instead.
What is a daemon?
A long-running background service with no controlling terminal (sshd, cron), created by forking, exiting the parent, and calling setsid().
What is a race condition?
When the result depends on the timing/interleaving of threads accessing shared data with at least one writing. Fix with mutual exclusion over the critical section.
What is a critical section?
Code that accesses shared data and must be executed by only one thread at a time.
What is a deadlock?
A set of processes each blocked waiting for a resource another holds, in a circle, so none can proceed. Needs all four Coffman conditions.
What is virtual memory?
An illusion that each process has a large private memory, with only the actively used pages in RAM and the rest on disk, brought in on demand. Enables running programs larger than RAM and strong isolation.
What is a page fault?
The exception raised when a process references a page not currently in RAM. The OS loads it from disk, updates the page table, and restarts the instruction. Not an error — the normal demand-paging signal.
What is thrashing?
When the system spends more time paging than executing because working sets exceed RAM. CPU utilization collapses. Fix: fewer processes, more RAM, working-set control.
What is the TLB?
A small fast cache in the MMU holding recent virtual→physical translations, so most memory accesses skip the page-table walk. Exploits locality; a hit is ~1 cycle.
Paging vs segmentation?
Paging splits memory into fixed-size pages (hardware, transparent, internal fragmentation); segmentation splits by logical units of variable size (programmer-visible, external fragmentation). Modern systems use paging.
What is an inode?
The on-disk structure holding a file's metadata and data-block pointers — everything except the file's name (which lives in the directory) and its data.
Hard link vs soft link?
A hard link is another name for the same inode (shares data; survives deleting the original; same FS only). A soft link is a small file containing a path (can cross FSs and link dirs; dangles if the target is removed).
What is a mutex?
A lock with an owner used for mutual exclusion: lock before the critical section, unlock after; only the locker may unlock. A blocked thread sleeps.
What is a semaphore?
An integer counter with atomic wait/signal, used to count resources or signal between threads. Binary (0/1) for mutual exclusion; counting (0..N) for N resources.
Concurrency vs parallelism?
Concurrency is dealing with many tasks over overlapping time (possibly interleaved on one core); parallelism is executing many simultaneously on multiple cores. Concurrency is structure; parallelism is execution.
What is a device driver?
Kernel code that knows a specific device controller's registers and presents a uniform interface to the OS, keeping the rest of the kernel device-independent.

Level 2 — Intermediate MECHANISMS & TRADE-OFFS

Mutex vs semaphore — which for what?
Mutex = ownership + mutual exclusion (protect data). Semaphore = counter + signaling (count resources or order threads). Use a mutex to guard a critical section; a semaphore to coordinate. Trap: a binary semaphore ≠ a mutex — no ownership, so any thread can signal it.
Spinlock vs mutex?
A spinlock busy-waits (burns CPU, no context switch — good for very short critical sections on multicore); a mutex sleeps (frees the CPU, pays two switches — good for longer waits). On a single core, spinning is disastrous.
Why are system calls expensive?
Each costs a mode switch (save/restore state, enter/leave kernel), the kernel's validation and work, and cache/pipeline disruption. That's why libraries buffer and systems batch I/O (writev, io_uring).
Why does context switching have overhead?
Direct cost: saving/restoring registers and switching address spaces. Indirect cost: the new process starts with cold caches and a possibly-flushed TLB, running slower until they warm. Thread switches within a process are cheaper (same address space).
Preemptive vs non-preemptive scheduling?
Preemptive can forcibly pause a running process (timer/priority) — better responsiveness, more switches; non-preemptive runs a process until it finishes or blocks — simpler, but a long job blocks others. Modern OSes are preemptive.
Explain FCFS, SJF, and Round Robin trade-offs.
FCFS: simple, suffers the convoy effect. SJF: optimal average waiting time but needs burst times and can starve long jobs. RR: fair, great response time, but average waiting time depends on quantum tuning.
What is the convoy effect?
Short processes stuck waiting behind one long process (classic FCFS), inflating average waiting time — like cars behind a slow truck.
Why does starvation happen and how do you fix it?
A process is indefinitely denied the CPU/resource because others are always preferred (priority, SJF, SSTF). Fix with aging — raise priority the longer it waits.
Name the four Coffman conditions.
Mutual exclusion, hold-and-wait, no preemption, circular wait. All four must hold for deadlock; breaking any one prevents it. Circular wait is easiest to break (lock ordering).
How do you prevent deadlock in real code?
Lock ordering — always acquire locks in a fixed global order, breaking circular wait. Also: request all resources up front (breaks hold-and-wait), or use try-lock with backoff.
What is the Banker's Algorithm?
A deadlock-avoidance algorithm: grant a resource request only if the resulting state is safe (a sequence exists letting every process finish). Needs max claims declared in advance.
Safe state vs unsafe state — does unsafe mean deadlock?
Safe: a sequence exists where all can finish. Unsafe: no such guarantee — deadlock is possible but not certain. Avoidance simply never enters unsafe states.
Deadlock vs livelock vs starvation?
Deadlock: all blocked, no motion. Livelock: busy but no progress (keep reacting to each other). Starvation: system progresses but one process never gets its turn.
Internal vs external fragmentation?
Internal: wasted space inside an allocated block (fixed partitions/paging's last page). External: free memory scattered in holes too small to use (variable partitions). Paging cures external, adds a little internal.
How does address translation work?
Split the virtual address into page number + offset. The MMU checks the TLB; on a miss it walks the page table to map page→frame; physical address = frame×pagesize + offset.
FIFO vs LRU vs Optimal page replacement?
FIFO evicts oldest (simple, suffers Belady's anomaly). LRU evicts least-recently-used (approximates Optimal via locality, costly to implement exactly). Optimal evicts the page used farthest in the future (best, but unimplementable).
What is Belady's anomaly?
For FIFO, adding frames can increase page faults. Stack algorithms (LRU, Optimal) are immune.
What is copy-on-write?
After fork, parent and child share physical pages read-only; a page is duplicated only when one writes it. Makes fork cheap and defers/avoids copying.
Contiguous vs linked vs indexed allocation?
Contiguous: fast access, external fragmentation, hard to grow. Linked: no fragmentation/easy growth, but no random access. Indexed (inodes): fast random access, no external fragmentation, small overhead — the modern choice.
Polling vs interrupt-driven I/O vs DMA?
Polling: CPU busy-waits and moves every byte (wasteful). Interrupt-driven: CPU works, device interrupts when ready (no waiting, but per-unit interrupts). DMA: hardware moves whole blocks to RAM, one interrupt per block (CPU nearly free).
Buffering vs caching?
A buffer holds data in transit (the only copy, moving A→B); a cache holds a duplicate of data stored elsewhere to speed future access. Buffer smooths a transfer; cache avoids a repeat.
Blocking vs non-blocking vs sync vs async I/O?
Blocking/non-blocking = whether the call returns immediately. Sync/async = whether the work completes before you proceed. High-scale servers use non-blocking + event notification (epoll) or full async (io_uring).
TCP vs UDP?
TCP: connection-oriented, reliable, ordered, flow/congestion control, byte stream — web, files, SSH. UDP: connectionless, best-effort, low overhead, keeps message boundaries — video, games, DNS.
Why is a socket "just a file descriptor"?
The OS models a network endpoint as an fd, so read/write and select/epoll work uniformly across files, pipes, and sockets — the "everything is a file" design.
Fastest IPC mechanism and its catch?
Shared memory — no kernel copy after setup. Catch: it provides no synchronization, so you must add semaphores/mutexes. Message passing is slower (kernel-copied) but safer.
SSTF vs SCAN disk scheduling?
SSTF serves the nearest request (efficient, can starve far requests). SCAN (elevator) sweeps to the end and back, serving all — no starvation, fairer. LOOK is SCAN without traveling to the physical edge.
RAID 0 vs 1 vs 5 vs 10?
0 = striping (speed, no safety). 1 = mirroring (safety, 50% capacity). 5 = striping + distributed parity (survives 1 disk, efficient). 10 = mirror+stripe (fast and safe, 50% capacity). Trap: RAID isn't a backup.
What is journaling and why does it help?
The FS writes intended changes to a journal before applying them, so a crash mid-update is recovered by replaying/discarding the journal — no full scan, no torn state.
User-level vs kernel-level threads?
User-level: managed by a library, fast, but one blocking call blocks all and no multicore. Kernel-level: scheduled by the kernel, true parallelism, blocking affects only that thread. Modern OSes use kernel threads (1:1).
Why can too many threads reduce performance?
Beyond core count you gain no parallelism but pay more context switches, lock contention, and cache thrashing. Sweet spot ≈ one thread per core for CPU-bound work.
What is a monitor?
A high-level construct bundling shared data with operations under automatic mutual exclusion, plus condition variables for waiting. Java's synchronized is a monitor.
Why must condition-variable waits use a while loop?
After waking, the condition may no longer hold (another thread changed it, or a spurious wakeup). Rechecking in a while guarantees correctness.

Level 3 — Advanced INTERNALS & PERFORMANCE

Walk me through exactly what happens when I run a program.
Shell forks; child execve's the binary; kernel builds a fresh address space and memory-maps the executable + libraries (demand-paged); dynamic linker resolves symbols; PC set to entry; scheduler marks it Ready; pages fault in as touched; C runtime calls main.
What happens during malloc()?
malloc (a user-space allocator) serves from its free list if possible; else grows the heap via brk or mmap. The kernel extends the virtual space but backs pages lazily on first write (often via a COW zero page). Most mallocs make no syscall.
What happens during read()?
Traps to kernel; resolves fd→open-file→inode; if data is in the page cache, copies it out; else issues a disk request and blocks the process (DMA does the transfer); on completion interrupt, data lands in cache + buffer, process becomes Ready, read returns and advances the offset.
What happens on a page fault, in hardware and software?
MMU raises the fault (present bit 0); kernel validates the address, gets a free frame (evicting one if needed), reads the page from disk (or zero-fills), updates page table + TLB, and restarts the faulting instruction. Minor faults skip disk; major faults don't.
What happens when you type a command in a terminal?
Keypresses interrupt the CPU; the driver buffers characters and wakes the shell blocked in read; the shell parses the line, forks, the child execs the command (wiring pipes/redirection with dup2), the parent waits; output is written back to the terminal.
How does a server handle 100k concurrent connections?
Not one thread per connection. Non-blocking sockets + an event loop (epoll/kqueue): a few threads ask the kernel which sockets are ready and service only those. This is how nginx/Redis/Node scale (the C10K solution).
Explain the effective access time with a TLB.
EAT = hit_ratio×(TLB + mem) + miss_ratio×(TLB + 2×mem). High hit rates (>99%, thanks to locality) keep it near a single memory access despite the extra page-table read on misses.
Why does the OS keep free RAM as page cache?
Idle RAM is wasted RAM. Caching file data in free memory turns repeat reads into memory hits and buffers writes. It's instantly reclaimable, so "low free" isn't a problem — watch "available."
Difference between the buffer cache and the page cache?
Historically the buffer cache held disk blocks and the page cache held file pages; modern Linux unified them — file data is cached as pages, keyed by (inode, offset), serving both reads and mmap.
How does copy-on-write interact with fork+exec?
fork shares pages COW; if the child immediately execs, the shared pages are discarded before most are ever written — so almost no copying happens. COW makes the common fork-then-exec path nearly free.
What is a major vs minor page fault?
Minor: the page is in memory (e.g. page cache or shared) and just needs a page-table mapping — no disk I/O. Major: the page must be read from disk/swap — expensive. /usr/bin/time -v reports both.
How do multi-level page tables save space?
They page the page table itself: unused regions of the address space simply have no lower-level tables, so a sparse address space costs little. Trade-off: a TLB miss walks several levels.
What is an inverted page table?
One system-wide table with an entry per physical frame (not per virtual page), saving space on huge address spaces; needs a hash to look up (process, page)→frame.
Monolithic vs microkernel — trade-offs?
Monolithic: services in kernel space, fast, but a driver bug can crash the kernel. Microkernel: services in user space, robust and modular, but slower (message passing). Linux is modular monolithic; QNX/seL4 are microkernels.
How does the CFS scheduler work?
It tracks each task's virtual runtime (CPU consumed, weighted by nice) and always runs the task with the smallest vruntime, picked from a red-black tree in O(log n) — approximating perfectly fair time-slicing.
Container vs VM?
A VM virtualizes hardware and runs its own guest kernel on a hypervisor (strong isolation, heavy). A container shares the host kernel, isolated by namespaces (visibility) and cgroups (limits) — light, fast, weaker isolation.
What are namespaces and cgroups?
Namespaces isolate what a process sees (PIDs, mounts, network, users); cgroups limit what it can use (CPU, memory, I/O). Together they implement containers.
What is ASLR and what does it defend against?
Address Space Layout Randomization randomizes the placement of stack, heap, libraries, and (with PIE) code each run, so attackers can't predict addresses for buffer-overflow exploits.
Explain the producer-consumer deadlock ordering bug.
If the producer locks the mutex before wait(empty) on a full buffer, it sleeps holding the mutex; the consumer can never lock the mutex to make space → deadlock. Always wait(semaphore) before lock(mutex).
How does TCP preserve reliability the OS must implement?
Sequence numbers, acknowledgments, retransmission on loss/timeout, reordering, checksums, and flow/congestion control — all in the kernel's TCP stack, so the app just reads a clean byte stream.
Why does write() often return before data hits disk?
The kernel copies data into the page cache, marks it dirty, and returns; background writeback flushes later. Use fsync for durability. This is why sudden power loss can lose recent writes.
What is priority inversion and how is it solved?
A high-priority task waits on a lock held by a low-priority task that a medium task keeps preempting — so the high task is effectively blocked by the medium one. Fix: priority inheritance (the holder temporarily inherits the waiter's priority).
How does mmap differ from read/write?
mmap maps a file into the address space so access is plain memory access (demand-paged), avoiding syscalls per access and extra copies, and enabling shared file pages. read/write copy through the kernel each call.
What is the dispatcher vs the scheduler?
The scheduler decides which process runs next (policy); the dispatcher performs the actual context switch and hands the CPU over (mechanism). Dispatch latency is the time for that switch.
How does the OS choose a victim page under memory pressure?
A replacement policy (approximating LRU via the clock/second-chance algorithm using reference bits) plus reclaiming clean cache pages first; dirty pages must be written back before eviction.
What is an interrupt storm and how do NICs mitigate it?
At high packet rates, one interrupt per packet overwhelms the CPU. Interrupt coalescing and NAPI switch to polling under load — the polling-vs-interrupt trade-off applied to networking.
Why can't you always preempt to break a deadlock?
Preemption only works for resources whose state can be saved/restored (CPU, memory). You can't preempt a printer mid-page or a lock protecting a half-updated structure without corruption.
What happens when RAM fills up completely?
The kernel reclaims cache and swaps pages to disk; if working sets exceed RAM it thrashes; if swap is also exhausted, the OOM killer terminates a chosen process to survive.

Level 4 — Deep / Senior DESIGN & WHY

Why separate fork and exec instead of one "spawn" call?
The gap between them lets the child customize its environment — redirect stdin/stdout, set up pipes, change uid, close fds — before becoming the new program. That flexibility (how shells build pipelines) is why UNIX split them. (Windows' single CreateProcess trades that flexibility for fewer steps.)
How would you design a scheduler for a mixed interactive + batch workload?
A multilevel feedback queue: new/interactive tasks start high with short quanta for responsiveness; CPU-bound tasks sink to lower, longer-quantum queues for throughput; aging prevents starvation. It self-classifies without knowing burst times.
Design a thread-safe, high-throughput bounded queue.
Mutex + two condition variables (not-full, not-empty), predicate loops on both; or a lock-free ring buffer with CAS and memory barriers for the highest throughput. Discuss the trade-off: simplicity/correctness vs contention.
When would you choose processes over threads?
When isolation/fault-tolerance matters (a crash mustn't take down siblings — e.g. browser tab-per-process), for security boundaries, or to sidestep a shared-memory bug surface / a GIL. Threads when you need cheap shared-memory concurrency.
Why is shared mutable state the root of concurrency bugs?
Because non-atomic read-modify-write on shared data can interleave, producing lost updates and inconsistent views. Remedies in order of preference: don't share (immutability/locals), share immutable data, or synchronize (locks/atomics). "Share nothing" scales best.
Explain memory ordering and why locks aren't only about mutual exclusion.
CPUs and compilers reorder memory operations; without barriers, one thread may see another's writes out of order. Locks (and atomics with the right memory order) also impose happens-before ordering, making writes visible — not just excluding concurrent access.
How do modern kernels reduce system-call and I/O overhead?
Batching (writev/readv), vDSO (serving cheap calls like gettimeofday without a real trap), zero-copy (sendfile, mmap), and io_uring (shared submission/completion rings that amortize or eliminate per-op syscalls).
Why is measuring "CPU utilization" misleading during I/O waits?
A process blocked on I/O isn't using the CPU, so utilization can look low while the system is I/O-bound (high iowait). Conversely, thrashing shows the CPU "busy" doing paging I/O. Look at run-queue length, iowait, and per-device utilization together.
How does virtual memory enable features beyond "more RAM"?
Isolation (per-process spaces), copy-on-write, memory-mapped files and shared libraries, demand loading, guard pages, mmap-based IPC, and ASLR — all fall out of the indirection between virtual and physical addresses.
Design the memory system for a database that must not lose committed data.
Write-ahead logging (log the change durably with fsync before acknowledging commit), a buffer pool it manages itself (often bypassing the page cache with O_DIRECT for control), checkpointing, and careful fsync/barrier ordering — the same journaling idea as filesystems.
Why do microkernels persist despite being "slower"?
For high-assurance/safety-critical systems (avionics, cars — QNX; formally verified seL4), fault isolation and verifiability outweigh raw speed. A driver crash restarts a server instead of panicking the kernel.
What are the trade-offs of larger page sizes (huge pages)?
Larger pages mean fewer TLB entries cover more memory (fewer TLB misses — great for big-memory apps like databases), but more internal fragmentation and coarser granularity for paging. Hence transparent/explicit huge pages as an option, not a default.
How does an OS provide isolation and still allow fast IPC?
Default isolation via per-process address spaces (MMU-enforced), with explicit, kernel-mediated holes: shared memory (fast, you synchronize), pipes/sockets (safe, kernel-copied), and zero-copy paths (mmap, splice) for volume. The kernel is the trusted mediator.
Explain the trade-off between throughput and latency in scheduling and I/O.
Batching and large quanta raise throughput (amortize overhead) but hurt latency/responsiveness; small quanta and preemption improve latency but add overhead. The right point depends on workload — interactive systems favor latency, batch/HPC favor throughput.
Why is "everything is a file" a powerful design?
One uniform interface (open/read/write/close + select/epoll) works across files, devices, pipes, and sockets, so tools compose and the same syscalls/multiplexing serve every resource. It minimizes special cases — the essence of good abstraction (Part I).
How would you debug a rare production deadlock?
Capture stacks of all threads (gdb/core, /proc/[pid]/task/*/stack, py-spy-style tools); identify the lock cycle (who holds what, who waits on what); confirm inconsistent lock ordering; fix by imposing a global order or using try-lock with backoff. Add lock-order assertions to catch regressions.
Why might adding CPU cores not speed up a program (Amdahl's Law)?
Speedup is capped by the serial fraction: if 20% must run serially, max speedup is 5× no matter how many cores. Lock contention, memory bandwidth, and coordination add further limits. Scaling requires reducing the serial/contended portion, not just adding cores.
How do you choose between blocking threads and an async event loop?
Blocking-per-task is simplest and fine at modest concurrency (thousands). Async/event loops win at very high concurrency or I/O-bound fan-out (tens of thousands of mostly-idle connections) by avoiding per-task thread cost — at the price of more complex, callback/await-structured code.
What consistency guarantees does the OS give for concurrent file writes?
A single write up to PIPE_BUF (pipes) or within one syscall is often atomic, but interleaved writes from multiple processes can mix without external coordination; ordering/durability need O_APPEND, locks (flock/fcntl), and fsync. Don't assume more atomicity than POSIX promises.
If you could add one hardware feature to simplify the OS, what and why?
A strong answer names a real tension — e.g. richer atomic primitives (transactional memory) to simplify synchronization, tagged/ capability memory for isolation, or better TLB/ASID management to cut context-switch cost — and explains which OS pain it removes. The point is showing you know where the OS fights the hardware.
